# Changes, October 28, 2026 (afternoon): Product Code Builder, link report, cross-graph stubs

## Product Code Builder (OII API) -> fda-compliance-kg

The import product code taxonomy behind import refusals, import alerts and entry lines, pulled
from the Product Code Builder REST API (https://www.accessdata.fda.gov/rest/pcbapi/v1/, OpenAPI at
scripts/ora/pcb/apidocs/src/main/pcb.json). Reads are GET with the OII Authorization-User and
Authorization-Key headers and a signature= cache-buster. Credentials come from an env file
(OII_ENV, default ~/.oii.env) and never touch the logs, the manifests or git.

L0 (`pipeline/fetch_l0_pcb.py`): `raw/fda-compliance-kg/fda-pcb/2026-10-28/` with the five global
lists (industry 89, class 1,159, subclass 117, pic 80, product 26,357) and five per-industry lists
(industryclass, industrysubclass 756, industrypic 939, industryproduct, productcodeindustry
3,041,333 codes), MANIFEST.json, SOURCE_URL, SHA256SUMS. 445 requests, about 8 minutes.

L1 (`pipeline/l1_pcb.py`, `scripts/build_pcb.sh`): `out/fda-compliance-kg/product_codes.ttl`,
41,813,061 triples.

| Class | Records | IRI |
|---|---|---|
| ex:ImportIndustry | 89 | import-industry/<INDID> |
| ex:ImportProductClass | 1,159 | import-industry/<INDID>/class/<CLASSID> |
| ex:ImportProductSubclass | 117 | import-subclass/<SUBCLASSID> |
| ex:ImportProcessIndicator | 80 | import-pic/<PICID> |
| ex:ImportProduct | 26,357 | import-industry/<INDID>/product/<PRODID> |
| ex:ImportProductCode | 3,041,333 | import-product-code/<CODE> |

A product code is industry (2) + class (1) + subclass (1) + PIC (1) + group (2), for example
16XYU46 or 17EM125 (class, subclass and PIC positions can be digits). Every code links to its
industry, class, subclass, PIC and product (ex:hasIndustry, ex:hasClass, ex:hasSubclass,
ex:hasProcessIndicator, ex:hasProduct); all 3,041,333 codes resolved every part against the
per-industry lists (zero unresolved). Industries carry ex:hasSubclass and ex:hasProcessIndicator
for the subclasses and PICs that apply to them. Every API column is kept; the all-caps column
names are mapped to readable properties (INDDESC -> ex:description, PRODID -> ex:productId, and
so on) rather than lowerCamel of the raw name.

Validation: riot clean. The first chunked SHACL run failed 18,648 codes on the productCode
pattern I had written (letters only in the class, subclass and PIC positions); the data was right
and the pattern was wrong, so the shape now allows digits there. Re-validation with the corrected
shape: 16 chunks of 200,000 blocks, all conform (full coverage).

Not yet done: linking the Data Dashboard import refusals (ex:productCode, ex:industryCode) and the
Import Alert scope and firm product rows to these nodes. That is an L2 step on the existing
files, no rebuild of the 33 M-triple Data Dashboard file needed.

## Cross-graph stubs (pipeline/l2_stubs_all.py)

Supersedes l2_stubs.py (same-graph only). Reads the dump and writes one stub per unresolved IRI
into the graph that owns the namespace: Firm stubs (with ex:feiNumber) in fda-compliance-kg,
NdcPackage, NdcProduct, DrugApplication and DrugProduct stubs in fda-drug-biologic-kg, Substance
stubs (unii or gsrs uuid) in fda-substance-kg. Each stub has ex:isStub true (accepted by the
shapes in place of provenance) and one ex:referencedBy per source graph and predicate. Output
`out/<graph>/l2_stubs.ttl`. First run from the second link report: 9,583 Firm stubs (47,915 triples,
conforms), 4,908 drug-biologic stubs (26,511 triples, conforms), 775 substance stubs (4 of them
GSRS reference child nodes, unii/<x>/references/<uuid>, typed ex:GsrsReferences). That report had
counted the October 13 l2_stubs.ttl as declared nodes, so the stubs are being regenerated from a
third report that skips every l2_stubs.ttl, and the counts above will move a little.

## Addendum (13:45): links to the product code taxonomy, drug_label verdict, final stubs

`pipeline/l2_product_code_links.py` -> `out/fda-compliance-kg/l2_product_code_links.ttl`
(1,334,179 triples, riot clean). Import refusals carry full 7-character codes or 5-character
codes without the group (86HQY); Import Alert rows use the spaced wildcard form (66 V - - 99,
77 - - - --). Every row gets the links its parts resolve to: ex:hasImportIndustry,
ex:hasImportClass, ex:hasImportProduct (industry + class + group) and ex:hasProductCode for a
full code present in the taxonomy. Results: 211,919 of 211,920 refusals linked, 128,106 of
128,686 Import Alert product rows linked (the 580 others are all-wildcard codes). Not resolved,
counted and left alone: 2,817 full codes and 11,394 product groups no longer in the current
builder (retired codes), 615 classes, 580 industries. The shapes for ImportRefusal,
ImportAlertProductScope and ImportAlertFirmProduct accept the four new link predicates.

drug_label.ttl.gz: the phase 3 summary line was a mix of true and false, and the first
per-chunk rerun produced empty reports. Cause: the validator ran out of heap at 3 GB on
200,000-block chunks of label text. Rerun at 100,000 blocks with a 6 GB heap: 6 of 6 chunks
conform (full coverage).

Final stub pass from the third link report (every l2_stubs.ttl skipped, so stubs come from L1
