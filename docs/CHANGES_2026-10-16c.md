# Change log, 2026-10-16 (night): full-coverage SHACL, tobacco L2 links, establishment registrations

## Full-coverage SHACL on the three big graphs
`pipeline/chunk_ttl.py` streams a Turtle file (plain or gzipped) through chunks of 400,000 node
blocks, prefixes repeated, runs a command on each chunk and deletes it. `scripts/shacl_full.sh`
validated every file of fda-drug-biologic-kg, fda-substance-kg and fda-animal-health-kg this way,
so every node of all six graphs has now been through its shapes (the earlier runs used slices).

| Graph | Files | Chunks | Result |
|---|---|---|---|
| fda-drug-biologic-kg | 10 | 15 | all conform |
| fda-substance-kg | 2 | 21 (gsrs_substance 20) | all conform |
| fda-animal-health-kg | 2 | 64 (animal_event 63) | all conform |

Peak memory stayed at one chunk (`JVM_ARGS=-Xmx8g`), disk at one chunk file.

## Tobacco products to marketing orders (L2)
`pipeline/l2_tobacco_links.py` joins Searchable Tobacco Products Database products to the
marketing-orders list on normalized company + product name (lowercase, punctuation out, corporate
suffixes out), since the orders list carries no STN. Result: 1,339 of 17,835 products linked
(1,339 `ex:hasMarketingOrder` triples, `out/fda-tobacco-kg/l2_tobacco_links.ttl`). The orders list
has 1,224 distinct name pairs, so most products simply have no order under the same name.

## Establishment registrations (fda-drug-biologic-kg)
- Drug Establishments Current Registration Site (DECRS, `drls_reg.zip` and `drls_excluded.zip`,
  official daily bulk files): `pipeline/l1_drls.py` writes `ex:DrugEstablishment` nodes keyed by
  FEI (`establishment/<FEI>`, 211 rows with no FEI keyed by DUNS), rows that repeat an FEI under a
  second DUNS or address merge onto one node with every value kept, `ex:Registrant` nodes by DUNS,
  `ex:hasFirm` to the FEI-keyed firm node of fda-compliance-kg. 10,109 establishments, 7,067
  registrants, 222,085 triples, conforms. The five contact-person columns (establishment and
  registrant contact names and emails, US agent details) are dropped by default and the shape
  forbids them (`--keep-contacts` exists for a private L1 only).
- CBER blood (eBER) and HCT/P (eHCTERS) registries have no bulk file. With Roche's approval
  (October 16, 2026) `pipeline/cber_fetch.py` pages the public query apps one request per second
  (one search per status, 100 rows per page, every list page and every detail page saved as
  gzipped HTML, resumable, SHA-256 manifest) and `pipeline/l1_cber.py` parses the saved pages into
  `ex:BloodEstablishment` and `ex:HctpEstablishment` nodes with child nodes for the product and
  operation matrix (blood), the HCT/P function, listing and donor matrices (tissue). The reporting
  official and US agent sections (names, phones, emails) are never written, only their organization
  line. The fetch is running; counts go in the next change log.
