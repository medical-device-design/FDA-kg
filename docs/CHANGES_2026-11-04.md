# Changes, November 4, 2026: MSSO answer, term text restored, registry entries, lakeFS dry run

## MedDRA: what the MSSO allows

The MSSO Help Desk answered the November 4 inquiry the same day: the preferred-term text that FDA
itself publishes (FAERS `reactionmeddrapt`, VAERS SYMPTOM1 to 5, CAERS and cosmetic `reactions`)
may be republished, with case or frequency counts. Posting the MedDRA code and hierarchy for each
term is not permitted (it would distribute MedDRA to unlicensed third parties). A follow-up asking
whether a bare PT code next to FDA's text, or aggregate SOC-level counts, would be acceptable is
with the PI. Until that answer, the rule is:

| Material | Status |
|---|---|
| FDA-published term text | public, restored by the `l2_term_text_*` files below |
| `meddra_29_1.ttl` (hierarchy, SMQs, history) | VM only, internal use under the subscription |
| `l2_meddra_*.ttl.gz` (term-to-code links) | VM only, internal use |

## lakeFS upload script (scripts/upload_lakefs.sh)

`--dry-run` lists every file, size and destination and checks the server, the repositories and
their `develop` branches; `--upload` sends files to `develop` only, with no commit, merge or
tag. MedDRA-derived files are excluded by name. The first dry run (11:13): server reachable,
none of the seven repositories exist yet, 65 files, 148.9 GB. With the four text files the plan
is 69 files, about 149.7 GB. The PI decided not to split the 125 GB FAERS file.

## Query testing: first attempt and lesson

A TDB2 dataset of the six smaller graphs plus VAERS and the MedDRA files (636 M triples loaded,
7 named graphs) was built on the VM between 12:54 and 16:57 (scripts/load_tdb2.sh). It took
253 GB, three times the estimate: TDB2's node table holds every literal once, and these graphs
are full of long label, narrative and section texts. That pushed the shared volume to 13 GB free,
under the 100 GB the device project is owed. With the PI's word the dataset was deleted at
20:40 (402 GB free afterwards). The reload will be sized first with one graph and kept under
100 GB, without VAERS, so the query battery (`queries/`, 24 queries) and the cross-graph joins
can run. FAERS joins are checked on a sampled chunk.
