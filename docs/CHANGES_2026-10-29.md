# Changes, October 29, 2026: FAERS finished and validated, every planned source complete

## What happened to the FAERS run

The drug/event conversion started on October 27 at 15:30 stopped on October 28 at 16:50 with
`zipfile.BadZipFile: Bad magic number for file header` on partition
`2025q4__drug-event-0027-of-0029.json.zip`. The October 27 download of that one file was a bad
transfer (105,227,579 bytes where the openFDA manifest says 91.06 MB). Python closed the output
stream on the exception, so `drug_event.ttl.gz` is a complete gzip of the 1,693 partitions before
it: 134.5 GB, 18,010,411,458 triples, riot clean. The build script had gone on to chunked SHACL on
that incomplete file; that run was stopped.

Fix, nothing deleted:
- the corrupt zip moved to `raw/fda-drug-event-kg/openfda-drug-event/2026-10-27/_corrupt/` with a
  README (sizes, both hashes, the error), and the old SHA256SUMS kept there as SHA256SUMS.before;
- a fresh copy of the partition downloaded (95,479,099 bytes, `unzip -t` clean), its SHA256SUMS
  line replaced, and the whole SHA256SUMS re-verified (1,767 files);
- `l1_openfda_any.py --from-zip NAME` added: converts that partition and every later one into a
  second file. The 74 remaining partitions (2025 Q4 parts 27 to 29 and all of 2026) became
  `drug_event_part2.ttl.gz`: 874,632 reports, 9.2 GB, 1,249,257,660 triples, 36 duplicate keys
  (the same report id in two partitions, both kept).

FAERS total: 20,692,690 reports, 19,259,669,118 triples in two files, publish mode (MedDRA
preferred-term text stripped, codes and outcomes kept).

## Lesson recorded

The build scripts keep only the SHACL summary line, and a chunk whose JVM runs out of heap leaves
no verdict at all (drug_label on October 28). Chunk sizes and heaps are now chosen per file, and
the streaming checker is the full-coverage pass for anything Jena cannot finish.
