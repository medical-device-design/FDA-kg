# Changes, November 3, 2026: MedDRA hierarchy and term-to-code links (licensed, VM-only)

## Subscription

Hofstra University received a non-profit MedDRA subscription (MedDRA ID 34423, December 1, 2026
to November 30, 2027, active now). The license covers internal use. Until the MSSO Help Desk gives a
written answer on redistribution, nothing derived from the MedDRA release leaves the build VM: not
the release files, not the hierarchy graph, not the term-to-code link files, not the unmapped-term
lists. The public L1 files stay in publish mode (MedDRA preferred-term text stripped). Only the
converters and shapes are in git.

Inputs: MedDRA 29.1 English, MedAscii distribution (`$`-delimited `.asc` files, CRLF, ASCII),
with `dist_file_format_29_1_English.pdf` for the field layouts, at
`raw/licensed/meddra/29.1/` on the VM (mode 750, SHA256SUMS written). The PC copy lives outside
OneDrive.

## Hierarchy graph (pipeline/l1_meddra.py, scripts/build_meddra.sh)

`out/fda-drug-event-kg/meddra_29_1.ttl`, 5,050,111 triples (272 MB, mode 640), one node per
term keyed by the 8-digit MedDRA code:

| Class | Nodes | IRI | Carries |
|---|---|---|---|
| ex:MeddraSoc | 27 | meddra-soc/<code> | name, abbreviation, international sort order, hasHlgt |
| ex:MeddraHlgt | 337 | meddra-hlgt/<code> | hasSoc, hasHlt |
| ex:MeddraHlt | 1,739 | meddra-hlt/<code> | hasHlgt, hasPt |
| ex:MeddraPt | 27,504 | meddra-pt/<code> | primarySoc, hasHlt, hasLlt |
| ex:MeddraLlt | 91,499 | meddra-llt/<code> | lltCurrency (19,006 non-current), hasPt |
| ex:MeddraHierarchyPath | 42,778 | meddra-pt/<pt>/path/<soc> | one mdhier row: PT, HLT, HLGT, SOC, primary flag |
| ex:MeddraSmq | 230 | meddra-smq/<code> | level, description, source, note, version, status, algorithm, hasMember |
| ex:MeddraSmqMember | 98,554 | meddra-smq/<smq>/member/<term> | term (PT, LLT or child SMQ), level, scope, category, weight, status, versions |
| ex:MeddraHistoryEntry | 142,768 | <term>/history/<n> | every row of meddra_history_english.asc: name, version added, type, currency, action (A, U, D) |

Every non-empty field in every file is kept (the legacy WHO-ART, HARTS, COSTART, ICD and J-ART
columns have been empty since MedDRA 15.0). Two details found while building: a code can name
both a PT and its identical LLT, so history rows are attached by (code, term type) rather than
by code alone (a first run doubled them to 198,442); and 7,692 (code, type) pairs in the history
file have no term row in 29.1 (deleted or demoted terms), so their history entries hang on the
same IRI scheme without a term node rather than being dropped. All 98,554 SMQ member codes
resolve to a PT, LLT or child SMQ.

Validation: riot clean, Jena SHACL on the whole file (6 GB heap) conforms, `stream_check.py`
conforms, 0 unparsed lines. Nine node shapes were added to `gen_shapes.py` for the graph
(code pattern, link namespaces, currency and status value lists).

## Term-to-code links (pipeline/l2_meddra_terms.py, scripts/build_meddra_links.sh)

The public files carry no MedDRA text, so the links are made from the raw snapshots and written
as separate small files that hold codes only. Matching against 29.1, in order: (1) PT name,
(2) LLT name (current or not, the LLT's PT linked too), (3) both with punctuation removed,
(4) a name the term carried in an earlier release (history file). Text is casefolded and
whitespace-collapsed first. Nothing else is guessed; unmatched strings are counted and listed
next to each output (`*.report.txt`, `*.unmapped.tsv`, VM-only).

| Source | Nodes linked | Occurrences | Match levels (occurrences) | Unmapped |
|---|---|---|---|---|
| VAERS symptom sets (`l2_meddra_vaers.ttl.gz`, ex:symptom<k>Pt/Llt/Match) | 4,994,174 of 4,994,174 (32,672,489 triples) | 16,220,557 (18,631 distinct) | PT 15,989,070; LLT 230,629; loose 11; history 847 | 0 |
| CAERS reports (`l2_meddra_caers.ttl.gz`, ex:hasMeddraPt) | 151,589 (844,449 triples) | 418,643 (5,513 distinct) | PT 410,510; LLT 7,998; history 13 | 122 (25 distinct, 0.03%) |
| Cosmetic events (`l2_meddra_cosmetic.ttl.gz`) | 85,511 (281,788 triples) | 140,893 (2,157 distinct) | PT 140,882; LLT 8 | 3 |
| FAERS reactions (`l2_meddra_faers.ttl.gz`, report/<id>/patient/reaction/<i>) | 62,097,285 of 62,097,430 (125,883,223 triples) | 62,097,328 (25,364 distinct) | PT 60,270,668; LLT 1,685,622; loose 138,789; history 2,206 | 43 (43 distinct) |

The CAERS and cosmetic leftovers are fragments of comma-split terms in the openFDA files
("Hallucination, auditory" arrives as two strings, "auditory" alone matches nothing). The 43
FAERS leftovers are free-text entries rather than MedDRA terms ("Skin began to feel hot",
"MINOR BLEEDING"). None are guessed. Reported MedDRA versions range from 8.1 to 28.1 (VAERS) and
17.0 to 28.1 (FAERS, top 15), which is why the LLT, loose and history levels matter: a term
renamed since the report was coded still resolves to its current code. The whole FAERS pass
took 32 minutes with four workers (about 1.1 s per partition).

The FAERS pass reads the 1,767 partitions with four worker processes and `ijson` events
(safetyreportid and the reaction list only, no record objects built), so the 134 GB L1 file is
never touched. All four link files pass `riot --validate`; they carry no typed nodes, so the
SHACL check is the one already done on the L1 files they attach to.
