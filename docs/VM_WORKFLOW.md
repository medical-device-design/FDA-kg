# FDA Regulated-Products KGs: workflow on the VM (.83)

This VM (10.22.12.83, Hofstra VPN) is shared by two projects run by two separate assistants
for the same PI. They never work in each other's tree.

| Project | Root | Code | Scope |
|---|---|---|---|
| Medical Device KG | `/srv/medical-device-kg` (`$MDKG`) | github medical-device-design/medical-device-kg | FDA devices (MAUDE, 510(k), PMA, GUDID, recalls for devices) |
| FDA regulated products (this one) | `/srv/fda-products-kg` (`$FDAKG`) | github medical-device-design/FDA-kg | everything FDA regulates except devices: seven graphs, fda-substance-kg, fda-compliance-kg, fda-drug-biologic-kg, fda-food-cosmetic-kg, fda-animal-health-kg, fda-tobacco-kg, fda-drug-event-kg |

Shared between them: the `mdkg` group (both trees are group-writable with the setgid bit),
the Jena and lakectl tools (`$FDAKG/tools/*` are symlinks into `$MDKG/tools`), the CPU
(8 vCPU), the RAM (19 GB) and the disk (1 TB, one volume). Nothing else.

## Layout of this project

```
/srv/fda-products-kg/
├── repo/           copy of the FDA-kg repo: pipeline/ (converters, gen_shapes, chunk_ttl), build scripts
├── repo/shapes/    SHACL shapes, regenerated by gen_shapes.py on every build
├── raw/<graph>/<source>/<YYYY-MM-DD>/   dated L0 snapshots: files as downloaded, SOURCE_URL, SHA256SUMS,
│                   MANIFEST.json for multi-part pulls. Never edited, never deleted without the PI
├── out/<graph>/    L1 Turtle per source (.ttl or .ttl.gz), each passes riot and the graph's shapes
├── work/           scratch for chunked SHACL and peeks; safe to clear when no job is running
├── logs/           one log per run, <job>_<date>.log, ending in "DONE <job>" when it finished
├── manifests/      per-build record counts
├── tools/          symlinks to the shared Jena, Fuseki, lakectl
└── env.sh          exports $FDAKG
```

Credentials: none live in this tree. The OII Data Dashboard key is in `~roche/.oii.env`
(mode 600, read by `fetch_l0_datadashboard.py` only, never printed or logged). lakeFS
credentials are in `$MDKG/.lakectl.yaml` and this project does not use them yet.

## Build conventions

1. Every source: L0 snapshot first (`fetch_l0_*.sh` or `.py`), then L1 (`l1_*.py`), then
   `riot --validate --count`, then SHACL with `gen_shapes.py` shapes, chunked through
   `chunk_ttl.py` for anything over a few hundred thousand triples.
2. Every field in the source is kept in L1. Only licensed terminology text (MedDRA) and
   named contact persons are left out, in publish mode, and the shapes forbid them.
3. Long jobs run under `nohup` with a dated log in `logs/`; the log ends with `DONE <job>`.
4. Before any build: `df -h /`; scripts abort below 12 GB free (150 GB for the big openFDA pulls).
5. Nothing goes to lakeFS until every planned database is built and validated, then one
   upload to the `develop` branch of each graph's repository, with the PI's go-ahead.
   No commit, merge or tag without the PI.

## Sharing the machine with the device project

- Check before launching anything heavy: `vm-status` (in `$FDAKG/tools/bin`, on PATH via
  env.sh) lists both projects' running jobs, memory, disk and load.
- RAM: keep any single JVM at or below 8 GB (`JVM_ARGS=-Xmx8g`), and do not start a second
  JVM above 4 GB while another project's JVM is running. The device project's Fuseki holds
  4 GB permanently and its TDB queries can take 6 to 12 GB for minutes at a time.
- CPU: the converters are single-threaded; one or two long Python jobs per project at a
  time is fine on 8 vCPU.
- Disk: both projects share the 1 TB volume. This project's raw/ and out/ are about 220 GB
  and FAERS is adding roughly 100 GB. Leave 100 GB free for the other project.
- Scratch: use your own `work/`, never `/tmp` for anything large, never the other tree.
- Logs and outputs stay in their own tree. Nothing of this project is written under
  `$MDKG`, and nothing of the device project under `$FDAKG`.
